# B站视频过滤器

Edge / Chrome 扩展，仅在 B站首页推荐流过滤原生视频卡片。按关键词、准确播放量、UP主粉丝数以及特殊话题个性化门槛判断，全部通过后才显示；不干扰主动搜索和浏览 UP主空间。

从 v0.8.0 开始，正常打开 B站即可使用；扩展图标打开的是设置与标记库，不再创建独立视频流。无需本地服务器。

## 安装与更新

1. 下载或克隆本仓库；在 Edge 打开 `edge://extensions`，Chrome 打开 `chrome://extensions`。
2. 开启开发人员模式，选择“加载解压缩的扩展”，指定本仓库的 `extension` 文件夹。
3. 更新现有安装时点击扩展的“重新加载”，核对版本为 `0.8.5`，并刷新已打开的 B站页面（包括旧版本已处理过的搜索页）。
4. 若扩展已禁用，需在扩展管理页重新启用；新版本增加了 B站页面内容脚本，浏览器可能要求确认网站访问权限。

点击扩展图标，或在 B站首页右下角点击“设置 / 标记库”，即可修改规则。旧版设置、标记和模型配置会自动复用，不必卸载重装。

## 使用范围与页面行为

从 v0.8.3 起，仅在 `https://www.bilibili.com/` 和 `/index.html` 首页推荐流自动筛选。搜索结果（包括 UP主空间内搜索）、UP主主页及投稿列表、播放页、动态、收藏和历史记录均不启用筛选：不隐藏视频、不调整排序、不显示检查占位或过滤面板，也不为这些页面发起筛选补查。

- 搜索使用 B站原生结果，完整保留视频，不调用扩展的筛选流程。
- 未完成检查的视频先显示占位，通过后展示原卡片，不通过则隐藏外层网格项。
- 通过的视频按 B站原有顺序连续补位；待查项移到后面，过滤掉和检查失败的项不占位。保留原生 DOM 与链接事件，首页轮播仍使用原尺寸。
- 在首页向下滚动或换一批时，新增和替换的卡片会自动检查。同一 BV 号复用结果。
- 保存设置后，已打开的 B站首页会遮住视频并按新规则重新检查，其他页面不受影响。
- 右下角显示通过、隐藏、待查和失败数量；“重试失败项”会重新检查失败视频。
- 通过的视频增加发布时间和“标记待分析”按钮，其余原生播放、UP主链接保持可用。
- 有合格内容的首页轮播保留 B站原生网格中的尺寸，隐藏推荐卡片后不会压扁；窗口缩放时重新测量。

插件不改变 B站后台推荐算法。原首页卡片保留其 DOM 与原有顺序；从 v0.8.5 开始，还会在推荐区下方追加来自 B站推荐接口的视频，仍在同一首页展示，不创建独立页面。

## 首页连续加载

设置页“首页连续加载”默认开启，保存后立即生效；关闭后撤掉追加区域，保留原有首页筛选。

- 先筛选原页面视频；靠近列表底部（约一屏预取距离）或筛选导致内容不足时，自动请求下一批 20 个推荐候选。已有足够内容时不继续预取，往下滚动后接着加载。
- 所有新增候选先走同一详情、关键词、话题、粉丝数与播放量检查，完整通过后才显示准确标题、封面、UP主、发布时间和标记按钮，不直接信任推荐列表里的摘要数据。
- 一次只加载一批，完成筛选再推进；按 BV 去重。原站后来也提供同一视频时，保留原生卡片并移除追加副本。追加网格跟随原首页列宽和间距，不覆盖搜索和 UP主空间。
- HTTP 412、网络或筛选失败时停止，不使用热门接口兜底，不自动重试或倒计时；可点击底部“重试加载”或右下角“重试失败项”立即恢复。服务端明确没有更多推荐时提示结束，也可手动再查。
- 正常滚动没有预设的总视频数量上限。但连续 5 批只有重复或没有合格视频时，会停止空转并显示“继续查找”，点击后可以继续；这不是风控冷却。
- 隐藏标签页不启动新的推荐分页请求；离开首页或关闭连续加载会清理追加区域并忽略迟到响应。已展示卡片保留在页面中，极长时间滚动会增加内存占用，刷新可开启新一轮，已标记样本不受影响。

## 规则与准确数据

设置页“首页内容类型”提供 **仅保留普通视频** 开关，默认开启，旧设置自动补全该默认值；保存后立即应用到已打开的首页，关闭状态会持久保留。

- 开启：推荐卡片的主跳转必须指向 B站普通 BV 视频，再通过原有详情接口确认对应稿件，继续接受关键词、播放量、粉丝数和话题门槛检查。直播、商品、活动、外链、番剧入口及无法确认类型的推荐不放行，隐藏后连续补位。导航、搜索框、网站顶部横幅等功能区不处理。
- 首页轮播同样检查：原始轮播 DOM 保留，启用时以通过筛选的视频元数据展示安全视图，可用“上一个 / 下一个”切换；不沿用含被隐藏项的原生轮播索引。没有合格视频时整个轮播收起、释放网格位置。不会把原生推广标题搭配到合格视频上。
- 关闭：撤销额外内容类型筛选，恢复非视频推荐及原生轮播；普通视频仍遵守既有筛选门槛，不等于关闭整个过滤器。
- 这不是广告识别开关：实际指向普通 BV 视频的推广，仍作为视频接受现有规则检查。

支持标题、简介、标签及可选 UP主名称的关键词屏蔽；粉丝数和播放量都可设置上下限。数值边界包含在允许范围内。

首页展示的“1.2万”等数值经过取整，不适合精确判断。因此扩展从卡片链接提取 BV 号，补查并缓存准确标题、简介、标签、分区、播放量和 UP主 ID，再为仍可能通过的视频查询粉丝数。详情或粉丝数据不完整时不会放行。

默认规则：屏蔽 `破防、急了、对线、开战、逆天`；粉丝数 1万～500万；播放量 5000～100万；检查标题、简介和标签。

## 特殊话题与本地 Qwen

在设置中添加话题，例如“华为”，填写最低播放量、最低粉丝数及置信度。特殊门槛只会收紧全局规则；同时命中多个话题时，各项最低门槛取最大值。

模型关闭时，按话题名称及补充关联词匹配；例如给“华为”补充 `鸿蒙, HarmonyOS`。

启用本地模型后，可只输入“华为”，由模型根据语义识别相关话题。默认接口是 `http://127.0.0.1:8000/v1/chat/completions`，模型名需与用户本地服务一致。

分类请求只向本机发送视频 ID、标题、标签和已有封面 OCR 文字，不发送 Cookie、粉丝数、播放量、简介、评论、字幕或弹幕。模型仅输出话题 ID、置信度和证据，门槛由确定性代码执行。模型失败、输出不完整或非法时，相关视频不会放行。

当前未捆绑 OCR 引擎，封面文字字段为空，实际分类输入为标题和标签。分类缓存为 7 天；键包含模型、接口、话题定义、提示版本和视频输入。

## 标记库与讨论样本

在原生卡片点击“标记待分析”，长期保存当时的标题、简介、分区、标签、数值、分类证据、有效门槛、来源和搜索词。在设置页“标记库”查看样本、添加备注、删除或复制 / 导出 JSON。

快照独立于缓存，清除缓存或 7 天分类缓存过期不会删除样本。每个浏览器配置最多保存 1000 个样本。可把导出的 JSON 提供给后续讨论，按具体视频信息调整规则。

## 请求调度与错误

首页补查使用高速模式，单类接口最多 4 并发。只处理视口附近的视频（轮播除外），每批最多 8 个 BV 号。连续加载每次只请求一批候选，不与下一批预取并行。标题、简介或播放量已不符合时，不再查询粉丝数。搜索页面不发起筛选补查。

视频详情与粉丝数缓存 24 小时。本地不设置风控冷却，不倒计时，不自动反复重试。遇到 HTTP 412 时停止页面自动检查，未确认的卡片保持遮挡；可立即点击“重试失败项”。B站服务器仍可能限制详情或粉丝接口。

仓库保留了旧版独立流使用的 WBI 签名和备用搜索函数，当前原页面过滤流程不调用它们。

## 开发与验证

需要 Node.js 20.19+（或 22.12+）：

```powershell
npm ci
npm test
```

可选联网测试：运行 `npm run test:live`，使用内存中的默认规则检查一个公开视频的真实详情和粉丝接口，不读取浏览器设置；也可用 `npm run test:live -- BV号` 指定视频。

`npm run test:live -- --home` 只请求一次真实首页推荐首批并输出候选数，不读取浏览器 Cookie 或设置、不自动翻页。Node 环境和已登录浏览器的推荐结果可能不同。

测试覆盖规则、分类、标记快照、真实后台消息处理、缺失数据 / 412、动态 DOM 新增与复用、迟到响应、设置更新和页面退出。连续加载另有纯控制器测试及本地静态夹具上的 Edge 完整内容脚本测试，覆盖滚动续页、补齐、去重、标记、412 手动恢复和关闭功能；不代替已登录 B站实际页面验收。B站卡片结构变动时可能需要调整适配器。

## 隐私与项目边界

设置、缓存和样本保存在浏览器本地，不自动上传。分类仅允许连接本机 localhost / 127.0.0.1。插件不下载或分析视频正文，也不包含字幕转写和 AI 总结项目。
