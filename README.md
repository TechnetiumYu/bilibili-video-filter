# B站视频过滤器

一个本地优先的 Edge/Chrome 扩展。它从 B站获取推荐或搜索候选，按关键词、UP主粉丝数、视频播放量和特殊话题个性化门槛进行过滤，在独立页面中只渲染全部条件通过的视频。

本项目只负责视频过滤，不包含视频下载、字幕转写或 AI 总结，也不捆绑模型权重。可选择连接用户自己的本地 Qwen OpenAI 兼容接口。

## 功能

- 屏蔽标题、简介和实际标签中命中关键词的视频；
- 搜索 B站视频，并对搜索结果应用完全相同的过滤门槛；
- 可选择是否检查 UP主名称；
- 设置 UP主粉丝数的最低和最高门槛；
- 设置视频播放量的最低和最高门槛；
- 为“华为”等特殊话题分别设置更高的最低播放量和最低粉丝数；
- 多个特殊话题同时命中时，各项门槛取最高值；
- 模型关闭时按话题名和补充关联词确定性匹配；
- 可连接本地 Qwen，让用户只输入“华为”也能语义识别“鸿蒙”等相关内容；
- 三项全部通过后才创建视频卡片；
- 粉丝数或视频详情无法确认时默认不显示；
- 页面滚动到底时自动继续筛选和追加视频，无需反复点击加载；
- 推荐/热门流每轮最多新检查 120 个，搜索每轮最多新检查 60 个；
- 视频卡片显示实际发布时间，不再重复显示规则通过提示；
- 个性化推荐不可用时自动使用热门视频候选；
- 粉丝数和视频详情缓存 24 小时，候选列表使用短期缓存。
- Qwen 话题分类结果缓存 7 天；缓存键包含视频输入、模型、话题定义和分类提示版本。
- 在视频卡片上标记待分析样本，长期保存标题、分区、标签、数值和分类证据；
- 在标记库中补充备注、删除样本、复制或导出讨论数据 JSON。

## 安装

1. 下载或克隆本仓库；
2. 在 Edge 打开 `edge://extensions`，Chrome 打开 `chrome://extensions`；
3. 开启“开发人员模式”；
4. 点击“加载解压缩的扩展”；
5. 选择仓库中的 `extension` 文件夹；
6. 将“B站视频过滤器”固定到工具栏。

安装后点击一次扩展图标，即可打开过滤首页。不需要提前打开 B站首页，也不需要运行本地服务器。

页面顶部可以直接搜索视频。搜索结果不会绕过过滤器：每个候选仍需通过关键词、UP主粉丝数和播放量三项判断后才能显示。点击搜索框中的清除按钮可返回个性化推荐流。

## 特殊话题门槛

在左侧“特殊话题个性化门槛”中点击“添加”，填写话题名称及更高门槛。例如：

```text
话题名称：华为
最低播放量：200000
最低粉丝数：100000
置信度：0.75
```

特殊门槛只会收紧全局规则，不会放宽它。例如全局最低播放量为 5000、华为话题最低播放量为 200000，则命中华为话题的视频使用 200000。播放量与粉丝数复用当前候选数据和已有缓存，不会因为话题命中而重复查询。

未启用本地模型时，系统只匹配话题名称和“补充关联词”。可以把 `鸿蒙, HarmonyOS` 填入华为话题的补充关联词，立即使用确定性规则。

### 连接本地 Qwen

在“本地 Qwen 语义关联”中启用模型并填写本机 OpenAI 兼容接口，例如：

```text
接口：http://127.0.0.1:8000/v1/chat/completions
模型：Qwen/Qwen2.5-27B-Instruct
```

扩展只允许连接 `127.0.0.1` 或 `localhost`，分类请求只包含视频 ID、标题、标签和已有的封面 OCR 文字，不包含 Cookie、播放量、粉丝数、简介、评论、字幕或弹幕。模型只负责返回固定话题 ID、置信度和证据；播放量与粉丝门槛始终由确定性代码执行。

当前版本已接好封面 OCR 文字字段，但不捆绑 OCR 引擎；在 OCR 适配器接入前该字段为空，话题判断实际使用标题和标签。模型接口不可用、超时、输出非法 JSON 或漏掉候选结果时，本轮候选严格不显示，避免特殊规则被静默绕过。

## 标记视频并积累分析样本

每个通过过滤的视频卡片都有“标记待分析”按钮。点击后会把当时的数据保存为长期快照：

- BV 号、标题、简介、链接与封面；
- B站官方分区名称和实际标签；
- 封面 OCR 文字字段（OCR 未接入前为空）；
- 播放量、点赞、弹幕、UP主名称与粉丝数；
- 模型命中的话题、置信度、原文证据和关联理由；
- 当时实际应用的特殊话题策略和最终有效门槛；
- 推荐/搜索来源、搜索词、标记时间和用户备注。

页面右上角“标记库”可以查看样本并填写备注。点击“复制讨论数据”后可直接粘贴到后续对话；数据较多时点击“导出 JSON”，再把 `bilibili-filter-marked-日期.json` 上传给我。我可以据此引用具体标题、分区、标签、话题证据和数值，讨论新增关键词、调整门槛或增加特殊话题。

标记快照与 7 天话题缓存分开保存：缓存过期或点击“清除全部筛选缓存”不会删除标记。单个浏览器配置最多保存 1000 个标记视频，删除标记需要在标记库中确认。

## HTTP 412 风控保护

扩展按使用场景采用两种速度：

- 推荐/热门过滤首页使用最初版本的高速模式：详情和粉丝数同时获取，两类接口分别最多 4 并发，不添加人工请求间隔，每轮最多检查 120 个新候选；
- 顶部搜索使用稳妥模式：最多 2 并发，新请求启动间隔约 200～300 毫秒，每组最多处理 8 个候选，每轮最多检查 60 个新候选。

两种模式使用完全相同的最终过滤规则。高速模式只改变数据获取调度，不会跳过关键词、标签、话题、播放量或粉丝数检查。

搜索模式采用节省请求的分阶段顺序：

```text
标题与已有播放量预筛
  → 直接复用搜索响应中的简介、分区和标签（缺失时才低速补查详情）
  → 关键词与特殊话题分类
  → 应用特殊话题播放量门槛
  → 只为仍可能通过的视频查询UP主粉丝数
  → 最终判断
```

这会避免为已被标签、话题或播放量拒绝的搜索结果查询粉丝数。推荐高速模式为了恢复最初速度，会并行获取详情与粉丝数。推荐和搜索候选在 2 分钟内直接复用；遇到 412 时，30 分钟内的旧候选可作为页面展示和后续处理的兜底。

搜索、详情和粉丝数属于公开数据请求，不携带 B站登录 Cookie；只有个性化推荐候选请求会使用当前浏览器的登录状态。这样既保留推荐个性化，也减少搜索被账号会话风控误伤的概率。

任意B站接口返回 HTTP 412 后，整个请求队列会统一暂停。连续触发的冷却时间依次约为 30 秒、2 分钟、5 分钟和 15 分钟。页面会明确显示触发风控的接口、剩余时间和待处理候选数量。已经通过的视频不会消失，未完成候选和当前批次会保存为最多 30 分钟的断点；冷却结束后自动继续，重新加载扩展页面也可以恢复断点。

## 默认规则

- 屏蔽词：`破防`、`急了`、`对线`、`开战`、`逆天`；
- UP主粉丝数：`1万～500万`；
- 视频播放量：`5000～100万`；
- 检查标题、简介和标签，不检查 UP主名称。

所有规则都可以在过滤页面左侧修改。数值边界为包含关系，例如最低粉丝数为 10000 时，粉丝数恰好为 10000 的视频可以通过。

## 工作原理

```text
B站推荐或搜索候选
  → 标准化数据
  → 关键词与播放量预筛
  → 查询视频详情，得到标题与标签
  → 本地确定性匹配或 Qwen 语义话题分类
  → 合并全局门槛和所有命中话题门槛
  → 获取或复用UP主粉丝数
  → 完整规则判断并记录实际命中的话题
  → 仅渲染 accepted 视频
  → 用户可将视频及当时的分类依据保存为长期标记快照
```

候选视频不会先显示再删除。页面只会为最终状态为 `accepted` 的视频创建卡片；查询中、查询失败和条件不通过的视频均不会进入视频列表。

## 隐私与限制

- 过滤设置保存在浏览器本地存储中；升级时会自动读取旧版同步设置；
- 粉丝数和视频详情缓存在浏览器本地存储中；
- 标记视频及备注保存在浏览器本地存储中，不会自动上传；
- 扩展不会把 Cookie、观看历史或推荐数据发送到第三方服务器；启用语义关联时只把限定字段发送到用户填写的本机接口；
- 个性化程度取决于当前浏览器中的 B站登录状态；
- 点击视频后会打开 B站原始播放页面；
- B站接口发生变化时，扩展可能需要更新。

本项目与哔哩哔哩官方无关。使用者应遵守网站条款和当地法律法规。
